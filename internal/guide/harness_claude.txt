Use para from Claude Code. (para help claude and para mcp --help-claude print this.)

1. Install para, then add one MCP server per vault. There are two transports.
   `para setup --agent claude` picks HTTP when the para service runs, else stdio.

   HTTP (para serve, port 7700): Claude Code talks to the service with an agent
   key. After a para upgrade the service restarts on the new binary; Claude
   Code reconnects to the same URL by itself, gets the new tools, and is told
   "para upgraded <old> → <new>: call changes". Make the key, then add it (the
   token is printed once and lives only in Claude Code's config):
   $ para --vault <vault> key create claude --scope agent
   claude mcp add --transport http --scope user para-<vault> http://<vault>.localhost:7700/mcp --header "Authorization: Bearer <token>"

   stdio (no service): Claude Code starts para mcp. `--scope user` makes the
   vault available in every project; drop it to keep one to this directory:

{{config}}

2. Install the skill, so agents load the rules when they need them:
   $ para skill install

3. Restart the session, then check with /mcp. After each para upgrade: run
   para skill install again (para setup does it). Over stdio a running server
   keeps serving; it refuses only the tools that changed (or every call, when
   the vault format changed) with a message to reconnect it in /mcp, and its
   first answer says once that para was upgraded. Reconnect then, or when
   convenient to get new tools and the fixes inside the tools. Over HTTP no
   reconnect is needed.

   Updates: para serve checks for a new signed release once a day (the manifest
   only; each vault logs an egress event update:manifest). On a release build
   it installs a newer release at a quiet moment and restarts the service; a
   build from a checkout only says one is available. Per machine, in
   $PARA_HOME/install.properties: upgrade.check=false stops the check
   (egress.default does not apply; a served vault with egress.update=deny
   stops all update traffic), upgrade.auto=false only announces, upgrade.vault_steps=auto also runs the
   automated vault steps (else they arrive as agent work "Vault upgrade: ...").
   The MCP server says when a newer release is available.

4. Asks are tracked. When you ask the agent in the chat for something that does
   not end in its reply (or that it hands to another agent), it records agent work
   of kind owner-ask: your words, the items it is about, and later how it ended
   and the receipts it made. A short answer in the same reply is not recorded.
   Prompts start as slash commands, such as /mcp__para-<vault>__orient.

5. The loop works the agent queue until it is empty: sweeps of your sources first,
   then what you asked, then other agent work. Run it once, or on a schedule:
   /para loop
   /loop 30m /para loop
   para serve queues a sweep per due source on its cadence; para itself reads
   nothing outside the vault. Each run spends tokens.

6. Check status:
   - web app (para serve): the requests view, tab Asked of agents (what you asked, its status,
     stale work, the queue, and the last sweep per source); Agenda shows
     "N asked of agents open (M stale)".
   $ para sent list
   $ para request list
   $ para health
   Work queued or claimed with no change in a day is stale (agent_work_stale).
   Events record the actor `claude`. Change `--actor` to tell agents apart.

7. Push into a session (optional). `para mcp` sends a short message
   (notifications/message, logger "para") when a request can be claimed by this
   install, or a request you claimed is cancelled.
   It holds ids and states only, never vault text. Whether Claude Code shows it is
   not verified. Claude Code channels show it in the session: add "--channel" to
   the server args (para then speaks only the initialize handshake, protocol
   2025-11-25 and older: Claude Code does not register a channel server on
   2026-07-28), and
   start the session with:
   claude --dangerously-load-development-channels server:para-<vault>
   Channels are a research preview, interactive sessions only; Team and Enterprise
   organizations must enable them in their settings first. If the server still
   does not register, start claude with MCP_PROTOCOL_NEGOTIATION=legacy in its
   environment.
   With two agents on one vault (this chat and a background dun), let only
   the background one be woken: dun with "wake": true, Claude without
   --channel. One claim wins, so they never do the same request; para agent
   list shows which agents are connected. Without push, `op_run {op: request_wait}` blocks
   up to 60 seconds, or a background job waits with no token cost:
   $ para request wait --timeout 1h

8. Optional: let para start the agent when a request can be claimed on this machine.
   THIS SPENDS TOKENS: every run starts a Claude Code session, billed to whatever
   account claude uses. Para starts nothing unless the file below exists on this
   machine. It is never in the vault and never synced. Write it with mode 600:

   $PARA_HOME/vaults/<vault>/agent.json
   {
     "command": ["claude", "-p", "Use the para tools: call work {action: next} to claim a request, work only on that request, report with work {action: note}, and finish with work {action: done} or work {action: fail}."],
     "max_concurrent": 1,
     "daily_limit": 10,
     "cwd": "/home/you/work"
   }

   command is an argument list, not a shell string. daily_limit counts starts per
   local day and survives a restart; max_concurrent is how many run at once. The
   environment of the command has PARA_REQUEST (the request id that woke it),
   PARA_HOME, and PARA_VAULT; nothing else from the vault is passed. Only the
   machine that is the vault's request runner starts anything.
   This example, claude -p with those words, is untested: it was written from
   the documented flags and was not run against a real session. Try the command
   by hand first, with PARA_REQUEST set, and check that the para tools are
   allowed for non-interactive runs.
   $ para agent status
   $ para doctor

Para cannot stop an agent from using other tools. The rule is in the prompts: no
outward act without an outgoing draft the owner approved. Para records the
owner's words with the approval, and what an agent reports is marked self-reported.
