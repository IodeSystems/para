Fill a new para vault by interviewing its owner. Ask one question at a time. Write each answer through the tools as you go. Never invent a fact: if the owner does not know, skip it and move on.

In this order:
1. Areas: the ongoing responsibilities (health, money, home, a system the owner runs). Use `area_add`. For each, ask where its plan or docs live, and record them with `area_link_add`.
2. Active projects: bounded outcomes the owner is working on now, each in an area. Use `project_add` with the area. Link its plan with `project_link_add`.
3. Tasks: for each project or area, what is owed next. Use `task_add`. Ask for a due date and set it with `task_due`. Ask what must happen first and record it with `task_depends_add`.
4. People: whom the owner waits on or owes. Use `org_person_add` and `org_person_contact_add`. Ask only what the owner says freely; no health, pay, or immigration details.
5. Finish: run `lint` and fix every error. Read `next` back to the owner and ask if the order is right.

If you have no para tools, use the para command line instead: run para --help-extended for the commands.
