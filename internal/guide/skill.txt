Use this when work touches para: tasks, blockers, asks to people, areas,
goals, policies, people, or anything the owner must review.

Each vault is an MCP server named para-<vault>. Use the vault the owner names. If
none is named, ask. Do not move work between vaults.

Start with the `orient` prompt, or read the rules below. Use `bootstrap` for an
empty vault, and `process_meeting` for a transcript. A write that can be
undone applies at once with a receipt. A change only the owner can decide becomes a
question (`question_add`). An outward act is an outgoing draft (`io_add` direction out)
the owner approves; send it with your own tool, then report it with `io_send`.

Arguments. If the request starts with the word health (as in /para health), use the
`health_triage` prompt: run `health`, settle what evidence settles with ops. With no argument, start with `orient`.

If the request is loop (as in /para loop), work the agent queue until it is empty with the prompt `loop`, then report and stop. Repeat it with `/loop 30m /para loop`.

Asks in the chat: when the owner asks for something that will not end in this reply, or that you hand to another agent, record it with `request_add` kind owner-ask (title in the owner's words, owner_said their message verbatim, links to the items) and end it with `request_done`. The owner sees it under Asked of agents.

If the request starts with the word ingest or align, the skill points to the reference file for it. The same text is the prompt `ingest_source` or `align_vault`.

Capture first: when the owner pastes or dictates material, save it word for word
with `io_add` (direction in) before you process it, and link what it became. If
the processing fails, point the owner to the io item. Waiting on a person is an
Ask, not a task (`task_to_asks`). Merge a duplicate with `doc_merge`; edit notes
with `notes_read` and `notes_edit` (pass the hash you read). An outgoing draft
waits for the owner: record their approval from the chat with `io_approve` and
their words, verbatim, in owner_said.
