# 0.5.0

## People

- The command line and the web app do not change. Every command and every web action works as before.
- An agent sees fewer ops: the listed ops went from about 302 to 236 (`para ops stats --json` lists 236 on a fresh install). Each removed op was a second way to do what a core tool does: show, edit, close, later, reopen, add, link, thread. Less to read, fewer wrong picks.
- The removed ops still exist inside para. The command line, the web app, receipts, and staged items use them, with the same gate, risk class, and receipt as before. An agent cannot list or run them.
- The REST paths of these ops are gone. A bearer client uses MCP or the command line. The web app keeps the routes it reads.
- `para journal daily|weekly|monthly` is unchanged. An agent uses one op, `journal {period}`.
- Reverting a response to a request (the revert mode of `request_respond`) is done on the command line only.
- The web app gets a typed show: one GraphQL union for the item's type. The web app only.

## Agents

- An op named in the table below is refused: `op_run` and `ops_describe` answer "X removed in 0.5.0: use Y". Use Y.
- New: `journal {period: daily|weekly|monthly}` makes the journal for that period. It replaces `journal_daily`, `journal_weekly`, `journal_monthly`.
- New: `link {from: person, to: group, rel: member_of}` puts a person in a group; `remove: true` takes the person out.
- `edit {id, fields: {aliases: [...]}}` and `edit {id, fields: {contacts: [...]}}` on a person replace the whole list. Send every entry you want to keep. To remove one entry, send the list without it.
- `request_respond` is `thread_post` for an agent. Reverting a response is not an agent action.
