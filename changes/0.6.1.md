# 0.6.1

## People

- A project can have KPIs: named numbers you track, such as weekly signups or open bugs. Each KPI has a unit, a target, a direction (up: at or above the target is good; down: at or below; hold: within a tolerance of it), and a cadence (how often it is read: daily, weekly, monthly, quarterly, yearly, or every n days).
- Define one with `para kpi add <project> <name> <target> --unit users --direction up --cadence weekly`. Add a reading with `para kpi reading add <project> <name> <value> --source <where you read it>`. A reading needs a source: a URL, a document id, or a path. `para kpi list <project>` shows each KPI with its readings. Change or remove a KPI with `para doc edit` on the `kpis` field.
- Para does not fetch a value. You or an assistant read it with your own tools and record it with its source.
- Health warns when the latest reading of a KPI is off target (`kpi_off_target`), and when a KPI has no reading within its cadence (`kpi_stale`). A KPI with no cadence is never stale.
- The project page shows a KPIs section: each KPI's latest value with a trend arrow, the target, the date and age of the reading, on, off, or stale, and its owner. Off and stale KPIs also show at the top of the page. Each row on `/projects` shows how many KPIs are off or stale.
- Add a reading on the project page: Add reading under the KPIs, then the KPI, the value, the source, and the date (empty is today). The source starts as `owner`, your own word; put a URL or a document id there when you read it somewhere. The control shows on your own sign-in (review:decide), like the state line edit.
- A KPI can have an owner: `para kpi add ... --owner self`, a person id, or `agent:<name>`. Change it with `para doc edit` on the `kpis` field. With owner `self`, a KPI that is off target or stale is one card in Next, with Add reading on it. A reading on target takes the card away. With owner `agent:<name>`, tick files one item of Agent work for that assistant: one while one is open for that KPI, and one for each new off reading or missed cadence. With a person as owner, the project page and health name the person; nothing goes to Next.
- `para goal edit <id> --status active|paused|parked` moves a goal; parked needs `--resume-when <what it waits on>`. `para list goal --status parked` lists the icebox; `--status` takes the status of any type.
- `para obligation add` makes a cron: `--project <project> --recur weekly --makes obligation|task`, and `--goal <goal>` for a task under a goal of the project. `--project` on `para obligation add` now takes an ongoing project; `--goal` (or `-p`) takes the goal id that `--project` took before.
- A journal can link a project: `para doc edit <journal> --field project=<project>`, or `project:` in its frontmatter. It then shows in the project's history, in date order with closed goals and the project's timeline.
- The project file keeps the last 12 readings of each KPI. On the machine named in `request.runner`, tick moves older readings to `archive/<project>-kpis-<year>.md`, one table per project and year. Only that machine writes the archive, so a file-sync tool sees one writer.

## Agents

- New ops through `op_run`: `kpi_add {id, name, unit, target, direction, tolerance, cadence}`, `kpi_reading_add {id, name, value, source, date}`, and `kpi_list {id}`. The core tools do not change. `value` and `target` are numbers. `source` is required: a URL, a document id, a path, or "owner in chat, <date>". Para fetches nothing.
- `edit {id, fields: {kpis}}` replaces the whole list. It checks the same rules: a unique name, direction up, down, or hold, a cadence in the recur grammar, and a dated reading with a source.
- The project bundle (`show {id}` on a project) has two new keys. `kpi_alerts` in the header lists the KPIs that are off or stale, at most 8, then "+N more". `kpis` has one line per KPI, alerts first, at most 8 lines and 600 bytes: `<name>: <value> <unit> <trend> vs <target>; <date> (<age>d); <on|off|stale>`. When lines are cut, `more` says to run `op_run {op: kpi_list}`.
- `list {type: project}` rows have `kpi_alerts`: the count of KPIs off target or stale.
- Health has two new kinds, `kpi_off_target` and `kpi_stale`. A stale KPI's fix names `kpi_reading_add`.
- `kpi_add` takes `owner`: `self`, a person id, or `agent:<name>`; `edit {fields: {kpis}}` checks it the same way (a person id must name a person). The bundle line ends in `; owner <owner>` when there is one, and the health messages do too.
- A KPI with owner `self` that is off target or stale is a row of `order`, kind `kpi`, id `kpi:<project>/<name slug>`; it is not a document. It goes away when a reading puts the KPI on target.
- A KPI with owner `agent:<name>` that is off target or stale gets agent work at tick: kind `kpi_alert`, linked to the project, its body naming the agent, the `kpi_reading_add` call, and a `KPI alert key` line. Tick files none while one for that KPI is open, and none twice for one alert (the same off reading, or the same missed due date). `para tick` output has `kpi_alerts`.
- A journal takes `project:`, a link to a project (lint: it must name a project). The project bundle's `history` lists it with kind `journal` at its date; the cap does not change.
- `obligation_add` is unchanged; on the command line `--project` now sets `project` (was `goal`), and `--goal` sets `goal`.
- `para tick` output has `kpi_archived`: `<project>: <n> readings to <archive ids>`.
