# 0.3.0

## People

- Later on the review stack: put a dossier item off until tomorrow, next week, or a date you pick. Later only sets when it surfaces: the default view and the count leave it out until its date, but a view scoped by a topic, a dossier, or a group, and the dossier's own page, list it with a "later until <date>" chip and Bring back. It returns on its date; Undo in the toast brings it back. `para defer --item <dossier>#<item>` and `para defer <dossier>` do the same at a terminal.
- Topics are tags: tag dossier items, whole dossiers, io items, and any vault document where they are (`para tag add socials --id <id> --item <dossier>#<item>`). `para tag list` and the topic chips on the stack count each topic's open, waiting, and put-off items; `para stack --tag` and a chip filter the stack. `para defer --tag socials --until 2026-11-09` puts a whole topic off.
- Skip is navigation, stored nowhere: s or Skip moves past a card at once (no note), it leaves the to-decide view for this visit to the stack, stays to decide with no date, and returns the next time you open the stack. A skip on a dossier page clears at Submit and the item stays to decide; a comment you wrote with it stays. A dossier Submit that decides nothing says "Nothing was submitted" with the reason for each item (`proposal_submit` left), and the N answered counter leaves out skips and comment-only answers.
- The stack and a dossier page show only what needs you: what you answered, sent to an agent, or put off leaves the list; the state chips and Show all items bring it back. A Sent to agent tab lists everything you sent with Send to agent, with its status and the agent's answer; take one back while no agent has it. `para sent list` does the same.
- Asked of agents (the stack tab that was Sent to agent) also lists what you asked an agent in the chat, when the work did not end in its reply: your words, who has it and since when, how it ended, and the receipts it made. Work queued or claimed with no change in a day is stale, and health names it (agent_work_stale). Below it, Queue and sweeps lists what waits for an agent, oldest first, and the last sweep of each source; the Sources page shows the last sweep and a failed one. Agenda shows "N asked of agents open (M stale)". Agent work that ended stuck, blocked, or needs clarification is listed at the top of the stack's needs-you view.
- `para help claude` and `para help dun` print the setup for that agent harness, as `para mcp --help-claude` does: MCP servers, the skill, tracked asks, the loop, and status. `/para loop`, alone or as `/loop 30m /para loop`, works the agent queue until it is empty.
- An io item can be put off too: it leaves the reply lane of `order` until its date.
- Evidence you are asked to approve must be checkable: a link, a vault document, or for a private chat item the agent's words on how to find it. Older items without one show "no way to verify", with Ask for a link. An incoming Slack, email, Jira, Confluence, GitHub, or Teams message needs its permalink, and the io page shows it.
- A new document in a change preview shows its fields and its text; diffs draw one line per row.
- `para feedback add` files feedback about para itself as an incoming io item tagged para-feedback.
- A vault upgrade step (format 6) marks the vault for these fields. Install this para on every machine of the vault first, then run `para vault upgrade` once. A para newer than the vault reads it; a para older than the vault's format now refuses it with a message.
- One rule decides what needs you, and the agenda, Today, the stack, and their counts read it: open, not put off, not an agent's turn, and your turn. Done and put-off items, and a failed task waiting to retry (health still names it), leave the agenda. An item you sent to an agent leaves every list while the agent has it. An optional meeting counts only when you said you go; the rest fold into one "N optional" line. A task that waits on another open item, an ask that waits on a reply, and a meeting more than order.due_soon_days away are not listed until they are your turn.
- Done, Later, and Reopen on every item row: the agenda (by order and by date, blocked tasks, the inbox), task lists, question lists, and a document's page. Done on a question or an io item is Drop, with why. Done's toast has Undo: it undoes the close from its receipt. A put-off row has Bring back. Task lists hide done and dropped tasks until Show done; the questions page lists closed questions under Show done, each with Reopen. `para close`, `para later`, `para reopen`, `para show`, `para list`, and `para send-to-agent` take any id.
- Agent writes apply at once when they can be undone: there is no rating, and nothing goes to a Staged writes dossier any more. Each has a receipt; Undo it on the Receipts page or ask the agent for `receipt_undo`. A write that cannot be undone is yours: an agent is refused vault settings (`vault config set` and `unset`, every key), `doc rename`, and archiving an item that other items wait on, and asks you to do it. Writes already staged in a dossier stay there until you decide them.
- An outgoing draft is sent only after you approve its exact text: `para io approve <id>`, or tell the agent in the chat and it records your words with io_approve (its receipt says self-reported). An edit of the draft after that makes it a draft again.
- The vault setting gate.require is no longer read. Health names it while it is set (gate_setting_unused); `para vault config unset gate.require` clears it, and setting it is refused.
- Tick (`para serve`'s timer, and `para tick`) marks a past optional meeting skipped (attend no) when you made no attend choice (unset or maybe) and it is still scheduled after its end. Each has a receipt, actor tick, that undoes it, and tick does not skip that meeting again. A meeting that is not optional, or one you said yes or no to, is never touched.
- Brief before a meeting: the meeting page and its agenda row show who is in it and, per person, the asks you made of them, what they asked of you (asks in, commitments you owe them), open tasks assigned to them or waiting on them, and open questions asked of them; the asks and items it is linked to; and the notes and outcome of the last held occurrence of a recurring meeting. An attendee not in the directory shows as unresolved. A meeting that needs you shows its brief on the agenda at once; other rows have a Brief button. The brief is read from the vault only, the same on every read. `para brief <id>` prints it.
- After a meeting: its page has Notes with Send to agent to file. The agent formats the notes, files decisions as answered questions, action items as tasks (for you or a person), and asks as Asks, then closes the meeting as held. `para send-to-agent <id> --file-notes` does the same.

## Agents

- An unknown input field is refused with the field you likely meant and the tool's fields on one line (* required, a|b values). Load a tool's schema before its first call.
- What you saw the owner do (an approval, a merge, a reply), with a locator and a time, closes the item it completes. Do not ask the owner to confirm it.
- Evidence locators must be a permalink (http or https), a vault id or path, or via {source, ref} with verify; proposal_add and proposal_revise refuse others. io_add with direction in on email, slack, jira, confluence, github, or teams needs ref, or via with verify.
- New tools: tag_add, tag_remove, tag_list, feedback_add. proposal_add, its blocks, and io_add take tags; proposal_stack takes tag. Tag existing items instead of withdrawing and refiling them.
- defer and undefer take items [{proposal, item}], a dossier's id, and tag; io items can be put off. Stack state later is new; proposal_list pending leaves put-off items out.
- proposal_stack takes needs_you; sent_list lists what the owner sent with Send to agent (requests of kind sent-to-agent).
- What the owner asks you in the chat that does not end in your reply is request_add kind owner-ask, with owner_said (their words, verbatim): it is claimed by you at once, stays with you when its lease ends, and you end it with request_done. sent_list lists it with sent-to-agent work, with stale, receipts, and counts. request_next claims sweeps first, then what the owner asked, then other agent work. Requests carry claimed_at and active_at. proposal_stack lists requests (work waiting on the owner) in the unscoped view. The prompt loop (/para loop) works the queue until it is empty. `para mcp --channel` answers as a server older than protocol 2026-07-28 (initialize only; server/discover is refused), since Claude Code does not register a channel server on 2026-07-28.
- report_friction only reads; file feedback about para with feedback_add.
- Rows of order, agenda, task_list, question_list, request_list, io_list, and proposal_stack carry needs_you and a reason (io_list and proposal_stack: needs_you_reason). order lists only what needs the owner: goals, agent work an agent has, tasks waiting on another item or a person, and asks waiting on a reply are left out; agent work to accept or that ended needing the owner is listed. agenda lists optional meetings with no yes in optional, not items, and no longer lists failed tasks to retry (kind retry).
- Generic verbs: close {id, outcome, reason, evidence, fields}, later {id|ids|items|tag|scope, until|after|when}, reopen {id|ids, reason}, show {id}, list {type, state, tag, needs_you}, send_to_agent {id, note, title}. Each runs the op of the item's type, with that op's rules and gate, and names it in op. close evidence, when given, must be a URL, a vault ref, or via {source, ref} with verify. reopen opens a closed item again (receipt, undoable); an item put off comes back with it too, which is undefer (people only).
- Old names are aliases for one release, and their output says alias_of: task_done, task_resolve, meeting_hold, meeting_cancel, question_drop, project_close, rfx_close, io_drop, request_cancel → close; defer → later; and the *_show ops of each type → show. Call the verb. An alias runs exactly what the old op ran: when the verb would run something else (question_drop on a task), the old op runs and refuses as before.
- A skip is not stored: stack_decide and question_review with skip change nothing and say so in note; proposal_submit clears a skip draft (its comment stays) and leaves the item pending. The batch input of proposal_stack, stack_decide, and question_review, and the skip_batch row field, are gone: batch is accepted and ignored for one release, with a note. Older skip_batch and skipped_at keys on disk are read and ignored, not rewritten; an item an older para marked skipped waits for the owner as pending.
- The gate: a write receipt_undo can reverse applies at once from any surface, with a receipt; that includes review ops, defer and later, and task_resolve failed or rerouted, which were held before. A write that cannot be undone is refused with "only a person can do this": vault_config_set and vault_config_unset (agent_may_set no longer lets an agent set a key), doc_rename (now marked not undoable), and doc_archive of an item other items wait on. Ask the owner. Writes are never staged: the staged output and REST 202 are gone.
- minor, obvious, dossier, and owner_said on a write are accepted and ignored for one release: the write applies and a note says so (MCP: a second text part after the output; CLI: stderr for --minor, --obvious, --dossier; REST: the X-Para-Note header for the X-Para-Minor, X-Para-Obvious, X-Para-Dossier, X-Para-Owner-Said headers). owner_said is not stored on those receipts.
- New tool io_approve {id, owner_said}: the owner's approval of an outgoing draft, from the chat only with the owner's words, verbatim; it binds the draft's medium, to, subject, and text (approved_hash) and sets state ready; the receipt is self-reported. io_edit no longer takes state ready from an agent, and an edit of the text, subject, to, or medium makes a ready draft a draft again. io_send of a draft that is not approved is recorded with a warning. A ready draft whose text changed after approval needs the owner again (needs_you "draft changed after approval").
- doc_edit of agent work (a request) from an agent is refused unless the agent holds it (claimed by you): text you read must not change what another agent runs. request_add from an agent is still only proposed.
- tick output has meetings_skipped: the past optional meetings it marked skipped this pass (meeting_attend receipts, actor tick).
- New tool brief {id}: a meeting's packet, built from the vault only (no model, nothing fetched). people (per attendee: you_asked, they_asked, tasks, questions; an attendee not in the directory has resolved false and unresolved), linked, previous (the last held occurrence: notes, outcome, skipped), done_when, agenda, and markdown (the same brief as text). Each line has id, type, status, and reason. It takes a meeting, a task with people, or an ask.
- Agent work of kind meeting-notes: the owner asked you to file a meeting's notes. Follow the prompt process_meeting, part Notes on a meeting: brief, format the notes (notes_edit), decisions → question_answer, action items → task_add with the meeting as parent, asks → rfx_add, then close the meeting as held. agent_send and send_to_agent take file_notes (people only).
