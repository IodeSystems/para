# 0.3.0

## People

- Later on the review stack: put a dossier item off until tomorrow, next week, or a date you pick. It leaves the stack and the pending count (filter Later shows it) and returns on its date; Undo in the toast brings it back. `para defer --item <dossier>#<item>` and `para defer <dossier>` do the same at a terminal.
- Topics are tags: tag dossier items, whole dossiers, io items, and any vault document where they are (`para tag add socials --id <id> --item <dossier>#<item>`). `para tag list` and the topic chips on the stack count each topic's open, waiting, and put-off items; `para stack --tag` and a chip filter the stack. `para defer --tag socials --until 2026-11-09` puts a whole topic off.
- An io item can be put off too: it leaves the reply lane of `order` until its date.
- Evidence you are asked to approve must be checkable: a link, a vault document, or for a private chat item the agent's words on how to find it. Older items without one show "no way to verify", with Ask for a link. An incoming Slack, email, Jira, Confluence, GitHub, or Teams message needs its permalink, and the io page shows it.
- A new document in a change preview shows its fields and its text; diffs draw one line per row.
- `para feedback add` files feedback about para itself as an incoming io item tagged para-feedback.
- A vault upgrade step (format 6) marks the vault for these fields. Install this para on every machine of the vault first, then run `para vault upgrade` once. A para newer than the vault reads it; a para older than the vault's format now refuses it with a message.

## Agents

- An unknown input field is refused with the field you likely meant and the tool's fields on one line (* required, a|b values). Load a tool's schema before its first call.
- owner_said lets an undoable safe write apply without minor and obvious; its receipt is self-reported.
- What you saw the owner do (an approval, a merge, a reply), with a locator and a time, closes the item it completes, rated minor and obvious. Do not ask the owner to confirm it.
- Evidence locators must be a permalink (http or https), a vault id or path, or via {source, ref} with verify; proposal_add and proposal_revise refuse others. io_add with direction in on email, slack, jira, confluence, github, or teams needs ref, or via with verify.
- New tools: tag_add, tag_remove, tag_list, feedback_add. proposal_add, its blocks, and io_add take tags; proposal_stack takes tag. Tag existing items instead of withdrawing and refiling them.
- defer and undefer take items [{proposal, item}], a dossier's id, and tag; io items can be put off. Stack state later is new; proposal_list pending leaves put-off items out.
- report_friction only reads; file feedback about para with feedback_add.
