# 0.4.1

## People

- A message whose source names the vendor (gmail) or the source id without its prefix now resolves to the declared source (source-gmail), in lint as at write time. Items written that way stop showing as source-unresolved; nothing is rewritten.
- A new message must name a source the vault declares, when the vault declares any; the error lists them. A filed, sent, or dropped message may still take one correction: a new source.
- The lint request filed for agents lists only what an agent can fix. Findings only you can clear (dossier-evidence on a proposal) stay in para lint, and the request says how many it left out. When only those remain, the open request is cancelled.
- para vault upgrade no longer lists a format marker as a pending automated step while an earlier judgement step still has documents; it shows again, and a run raises the format, once those are done.
- para --version works, as para version does.
- bin/t keeps test vaults on tmpfs again under Go 1.27 (t.TempDir moved to GOTMPDIR): internal/ops runs in about 30 s, not past the 10 minute limit.

## Agents

- add: parent sets the item's project, area, or parent; do not repeat it in fields. A task needs fields.done_when.
- close: a question or an Ask is answered with outcome answered and answer.
- ops_describe {query} matches word forms (reviewed finds review). An op only people run is named at the end: ask the owner for it.
- ops_describe {op} lists each shared write field once, with its type; an op's own why or sources shows as the op declares it.
- list {} means list {needs_you: true}. list takes type goal for project and ask for rfx, as add does.
- question_answer, and close {outcome: answered} on a question, take choice as the answer text when the question has no options.
- io_add and io_edit refuse a via.source the vault does not declare. On a filed io, io_edit takes only a new via.source.
