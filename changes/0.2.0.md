# 0.2.0

## People

- The web app decides again, for review items: open a dossier, answer each card (approve, reject, edit, pick options, add your own), comment on sections, and Submit. Answers save as a draft while you type. Approved vault changes run at once; approved messages and actions wait for an agent to carry them out and report a link.
- New Review stack page: every item agents put in front of you, with counts per state (proposed, decided, executing, done, failed), filters, group progress, approve-group, and keys.
- Agent writes now land in the review stack unless the agent rated them minor and obvious and receipt undo can reverse them. Writes the agent did not rate wait in its "Staged writes" dossier, grouped by op, until you approve them. Loosen this with `para vault config set gate.require` (undoable, minor, obvious, or none).
- Answers typed into a dossier file in an editor stay a draft until you run `para proposal submit <id>`. A file edit alone never decides.
- `para serve login` keys now hold vault:read and review:decide.
- A vault upgrade step rewrites open proposals in the old one-block form as dossiers.
- The inbox is now io: messages not dealt with yet, in both directions. Incoming ones (unread, read) wait to be filed into a task, question, Ask, note, or interaction, or dropped with a reason. Outgoing ones are drafts (draft, ready) that say whether they expect a response: when sent, one that expects none becomes an interaction, and one that expects a response becomes an Ask you can follow up. `para io inbox` and `para io outbox` list them; the web app has an IO page, and Agenda shows the unread and ready counts.
- A vault upgrade step moves inbox/ captures to io/ as unread incoming items. Ids stay, so links still work. Captures triaged before stay in archive/ as they are.
- `para inbox add` still works for this release, as `para io add --direction in`. `inbox list`, `inbox show`, and `inbox triage` are gone: use `io inbox`, `io show`, and `io file` or `io drop`.

- Tracked documents: a remote document you follow (a wiki page, a ticket, a pull request) keeps its original and every version in the vault, under tracked/. `para doc tracked` lists them with versions you have not seen and open comments; `para doc diff` shows what changed since you last looked, and `para doc seen` marks it read. People's comments keep the words they are about and become Asks, questions, or commitments. The web app has a Docs page: versions, a diff between any two, comments highlighted in the text, and Mark seen. Agenda counts unseen documents and open comments; health names changes not seen in a week, comments open for a week, and, with `para vault config set docs.check_days`, documents no agent has read again.
- A dossier can show a document's change with its comments (upstream): approve marks it seen and turns each comment you answered into what you chose. An approved edit to a tracked document is recorded as its next version.
- Sources (optional): a source document in sources/ says where work comes in or goes out (a mailbox, a calendar, a chat, a tracker, a wiki, a folder), how an agent reaches it (an MCP connector, which may live only inside the agent; a command line tool on this machine; or words), what to scan, and how often. `para source example <system>` prints one to copy for gmail, gdocs, gcal, slack, github, jira, confluence, or folder; `para source add --example <system>` makes one. No token or key goes in a source: lint refuses one. `para source list` and the web app's Sources page show each source's cadence, last sweep, who reaches it, and whether it is overdue.
- Each agent declares the sources it reaches at the start of a session; the declaration stays on this machine, not in the vault. With `para vault config set sources.learn_reach true` a declaration also adds the agent to the source's reached_by. `sources.reach_days` (default 7) is how long a declaration lasts.
- Sweeps: `/para sweep` has an agent read its due sources and bring the vault up to date. On the runner install, para serve queues one sweep request per due source (queued when request.surfaces lists tick, else proposed); only an agent that declared the source can claim it, and para makes no second one while it waits. Health names sources no agent reaches, late sweeps, and items whose via.source names no source; `para doctor` checks that the commands of command line sources are on PATH.
- Sign in once: `para serve login` signs this browser in to every vault the server serves (one tab per vault; `--vault` for one) with a login key that lasts 30 days (`--days`, at most 90). The web app renews the key when it is within 7 days of its end, so a browser you use at least once a month stays signed in. `para serve sessions` lists the login keys (vault, created, expires, last used); `para serve logout` revokes them.
- `para open` signs the browser in when no login key of the vault is active: the key goes only on the browser command line, never in the output. When it opens nothing, it says why (no graphical session, an SSH session, no xdg-open, no server) and what to do, and opened is false. With no server.base_url, url_note says the URL works only on this machine.
- The sign-in page says "Not signed in" with the command to run. A read-only key shows a banner that review actions need a new login.
- Close outcomes: a task can now end declined (someone said no: reason, who, and where or when), failed (what was tried and why it stopped; with a retry date it comes back in health and the agenda), or rerouted (another task, Ask, or an outside system holds it). `para task list --outcome failed` finds failed tasks. Declined and dropped close the open Asks that hang on that task only, with the reason; failed and rerouted list them for you to decide.

## Agents

- Unrated agent writes now land in the stack: a write applies directly only when it is undoable, minor, and obvious (vault setting gate.require; agents cannot change it). Pass minor and obvious on a write tool (CLI --minor --obvious, HTTP X-Para-Minor and X-Para-Obvious). Any other write is staged as a change item in your dossier (dossier, else "Staged writes <you>") and the call reports staged: a success, do not retry.
- Prepare one dossier per investigation: proposal_add with markdown, narrative plus one "yaml para-<question|change|message|action|doc-edit> id=<id>" block per item and one "yaml para-dossier" header block. Every block needs evidence. Do not write answer, state, or exec.
- proposal_revise with markdown rewrites the dossier in place: unchanged items keep the owner's answer, changed ones are asked again, dropped ones are withdrawn. proposal_diff reads the receipt of the old body.
- New tools: proposal_response (the owner's answers and your todo in one call), proposal_claim (take approved outward items with a lease), proposal_reply (answer a comment), proposal_stack (the review stack). proposal_executed accepts claimed items.
- On submit, para runs approved vault changes itself under your name. Do not run them again.
- io replaces inbox. New tools: io_add (direction in captures; direction out drafts, with to, expects response or none, route for response), io_list, io_show, io_edit, io_file (to task, rfx, question, note, interaction, project, or existing), io_drop (with reason), io_send (url or locator; expects none logs an interaction, expects response opens an Ask with sent targets). inbox_add, inbox_list, inbox_show, and inbox_triage are removed; a staged inbox_add item fails when approved.
- A para-message block may name an outgoing draft with io: "[[io-x]]" and leave out people, subject, and body. The draft holds the text: an owner's edit is written to it, approval makes it ready, an io_edit after approval stops proposal_executed, and proposal_executed done marks it sent and files it.
- Tracked documents. New tools: doc_track (url, the text you read, system, via, owner, watchers, area, project: version 1), doc_version_add (the text read again; the same hash stores nothing; reports anchors_lost), doc_diff, doc_tracked, doc_tracked_show, doc_tracked_status, doc_comment_add (quote the document's words), doc_comments, doc_comment_resolve, doc_comment_file (to ask, question, or commitment). doc_seen is the owner's. Prompt track_doc; the skill routes /para track. Vault setting docs.check_days (agents may set it).
- para-upstream blocks are real: target (a tracked document), from and to (default last seen and latest), comments. Para runs one when the owner approves it. A para-doc-edit block on a tracked document needs old as it is in the latest version, or proposal_add refuses it; report the done edit with proposal_executed and text (the document after the edit), which becomes the next version.
- Sources and sweeps. New tools: source_list, source_show, source_add (start from example <system>), source_status, source_example, agent_sources (call it at session start with the source ids you reach now; it lasts sources.reach_days), sweep_plan (the declared sources that are due, with filled templates, cursor, since, and the io items, drafts, Asks, and tracked documents to match), sweep_record (cursor, counts, errors, failed; name the sweep request to end it). Prompt sweep; the skill routes /para sweep. request_next gives a sweep request (kind sweep, requires_source) only to an actor that declared its source. A via.source that names no source document is a lint warning (source-unresolved) when the vault has sources. In the web API, Meta via and state are now JSON: a source's via is a word and its state a step.
- proposal_open never signs the browser in. Its output has opened, reason (no_server, no_display, remote, no_opener, opener_failed, not_here), and a note; when the owner holds no active login key the note says "the owner is not signed in; run `para serve login`": pass that on. url_note says a URL works only on this machine.
- task_resolve takes outcomes declined (reason, declined_by owner or other, optional declined_person, source or date), failed (tried, stopped_because, optional retry_after), and rerouted (to: a vault id or URL, reason); its output lists affected Asks (asks: id, relation, action closed or needs_decision). Gate: failed and rerouted are always staged unless the call carries owner_said; declined with declined_by owner passes with owner_said. Use dropped only when nobody needs the work any more.
