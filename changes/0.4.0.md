# 0.4.0

## People

- An agent sees 15 tools, not 258: search, show, list, add, edit, link, tag, close, later, reopen, work, undo, thread, ops_describe, and op_run. Each other op is still there: ops_describe finds it and op_run runs it, with the same checks, gate, and receipt as before. The command line and the web app do not change.
- Less context per agent session. Measured with the budget test: the tool list was 322 KB (about 80k tokens) in 0.3.1 and is 11 KB (about 2.7k tokens) now; the session instructions are 7 KB.
- para mcp and para serve's /mcp list the 15 core tools by default. For a client that needs one tool per op, set mcp.tools=all in $PARA_HOME/install.properties, or run para mcp --tools all.
- para ops stats counts the calls of each op on this machine, by surface and actor, so the ops nobody uses can go in a later release.

## Agents

- Your tool list is 15 tools: search, show, list, add, edit, link, tag, close, later, reopen, work, undo, thread, ops_describe, op_run. For any other op: ops_describe {query} finds it (ops_describe {op} gives its fields), and op_run {op, input} runs it with the same checks and receipt. An unknown field is refused with the field you likely meant.
- add {type, title, parent, body, tags, fields} makes any item: task, question, project (goal), area, person, group, obligation, note, ask (rfx), or io. Inputs of the type's own add op go in fields.
- close takes the outcomes of every type: answered (a question or an Ask, with answer or choice and sources), no and partial (an Ask), sent (an io draft: it runs io_send_check first), dropped, declined, failed, rerouted, and the rest.
- show returns the item's notes and notes_hash; edit {id, notes, notes_hash} replaces them.
- list {needs_you: true} is ranked as the order op ranks it (rank, group): use that order as it is.
- Fields that decided nothing are gone: minor, obvious, and dossier are refused as unknown fields. owner_said counts as approval only on io_approve.
