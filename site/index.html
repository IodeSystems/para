why we built it

Work stalls on people, not on effort.

We run a company, hold a day job, and have a life, each with its own mail, chat, and tracker. What stops progress is rarely the work itself. It is the reply nobody sent, the answer that arrived in a thread no one reread, the approval someone gave in passing that nobody wrote down.

Agents can now read all of those sources. But an agent that acts as you, unchecked, with your account keys, is a new risk, not relief. So we built the part in between: a plain-file ledger the agent keeps current, with you deciding what happens and what leaves.

Progress without pain.

  • Drive each goal to done without chasing people or becoming the one everything waits on.
  • Every blocker is written down: why, who said it, and where it applies.
  • Every reply you owe is on the list before anyone has to ask twice.
  • Your agent files; you decide. One card at a time.

how a day goes

Your agent files. You direct.

Four moves, and the agent does the clerical part of each.

Sweep

Your agent reads your mail, chat, tracker, and calendar with its own tools. Each message becomes a reply you owe, a task, an answered question, or a line in a digest. Input shows what each one created, edited, or closed.

Next

One rule decides what needs you, and Next ranks it: what is due, what you owe someone, quick replies, then the best payoff for the effort, weighted by your goals' dates. Pin the plates you are juggling.

Talk

Every item has a thread: change it, question it, redirect it. Press t on any page to capture a call or a hallway promise; the agent files it with the detail as you said it.

Approve

A reply, a PR, a ticket: each is a proposal first, with why, impact, risk, and confidence. Compare variations, ask for a revision, approve the exact text. para records what was sent.

what it keeps

Everything you are on the hook for, in one place.

Organized the PARA way (projects, areas, resources, archive), plus what PARA leaves out: what came in, and what goes out.

goals

Bounded, with a done-when

Tasks form a graph with dependencies and blockers that carry reasons. The agent breaks a goal down and keeps it moving; you see what is stuck and why.

areas

Ongoing responsibilities

Health, money, a client, a system you run: each with its policies, exceptions, and a review date. Agents quote the source and link it, so you know what holds.

people & asks

Who decides, and what you asked

People and groups, how to reach them, and every Ask with its answer, or a "no" with its reason, where it applies, and when to ask again.

documents

Linked, not copied

Plans and docs stay where they live. para links to them and tracks their versions and comments, so it never holds a stale second copy.

history

Every write has a receipt

Each agent change carries why, sources, and a diff, and most can be undone. Closed work keeps its outcome. Activity shows who changed what, on every machine.

vaults

One per front

Keep your company, your job, and your life in separate vaults. A work vault opens only on the work machine; the rest can share one desktop.

Any MCP client

Setup registers the server and installs the skill. Then open your agent and run the bootstrap prompt: a short interview that fills your first vault. An agent with only a shell can use para --actor NAME --why "reason" <command>.

trust

Safe to point an agent at.

para holds what you owe, so these are enforced in the code, not left to a setting.

  • No logins to your accounts.para never asks for access to your mail, chat, or code hosting, and stores no tokens for them, so it has nothing of yours to leak. Your agent reads your sources with the tools it already has and hands para the text and a link.
  • Nothing goes out without you.A reply, a PR, or a ticket stays a proposal until you approve its exact text. Every connection para makes is logged.
  • Your files, readable without para.A vault is a folder of markdown (Obsidian format). Open it in any editor; git is optional. The database is a cache para rebuilds from the files.
  • Every change is accounted for.An agent's write carries why, sources, and a diff. A hand edit is noticed and recorded. The log holds ids and hashes, never your text.
  • Closed by default.The web server answers only the machines and keys you allow, and no switch turns the checks off.
  • Work data stays on the work machine.Each vault has a domain. It opens only on a machine you allowed that domain, and only you change that list, from the terminal. No agent can.
  • Sync with what you already use.Syncthing, Dropbox, iCloud, or git: a vault stays correct under any of them, because each machine keeps its own state outside the vault.
  • Updates are signed.para checks for a new release once a day, sending nothing from your vaults, verifies its signature, and installs it at a quiet moment. A vault setting turns it off.

install

One command, then one setup.

Linux and macOS, amd64 and arm64.

$ curl -fsSL https://para.iodesystems.com/install.sh | sh
$ para setup

Installs the latest release to ~/.local/bin. Needs minisign: it checks the release signature, that the release is para's, and the tarball's sha256, and installs nothing if any check fails. Refuses to run as root. Read the script.

$ git clone https://github.com/IodeSystems/para.git && cd para
$ bin/doctor       # git, make, Go, node, pnpm, PATH
$ make install     # builds the UI and para into ~/.local/bin
$ para setup

Fix every FAIL line from bin/doctor first.

para setup asks about domains, the first vault, the service, sign-in, and an optional agent. A rerun skips what is done; --dry-run prints every step and changes nothing. The web app is on port 7700.

Verify a release yourself

Each release has a manifest with every tarball's sha256, signed with minisign, key ID 2CC27A171DE03D42. Get the key from this site (minisign.pub), compare the ID, then verify:

$ curl -fsSLO https://github.com/IodeSystems/para/releases/latest/download/para-manifest.json
$ curl -fsSLO https://github.com/IodeSystems/para/releases/latest/download/para-manifest.json.minisig
$ minisign -V -p minisign.pub -m para-manifest.json
